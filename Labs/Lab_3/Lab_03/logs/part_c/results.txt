=================================

strace observations
-------------------
Host summary (2/20/1000 workload): 57 syscalls, one failed call, 0.000535 s
summed syscall time. Highest entries by measured syscall time were munmap
(27.29%), mmap (26.17%), write (11.21%), and openat (10.28%).

QEMU ARM guest summary for the same workload: 68 syscalls, seven failed calls,
0.012424 s summed syscall time. Highest entries were write (15 calls,
25.89%), openat (7 calls, 20.77%), munmap (6 calls, 14.62%), and mprotect
(6 calls, 10.86%). The openat/statx failures are loader search probes for
library/cache paths not present in this minimal rootfs; getrandom returned
EAGAIN for a nonblocking request; this did not prevent successful program
execution.

Interpretation:
- openat locates libraries and opens /tmp/perf_test.txt; write emits buffered
  file and console output; close finalizes the output file.
- mmap/mmap2, mprotect, and munmap are primarily dynamic-loader and process
  memory setup/teardown activity. They do not measure the application's
  compute hotspots.
- strace measures system calls, not CPU instruction samples. Host and guest
  syscall totals differ because of their libc/loader/runtime environments.
  The traced times are not directly comparable as CPU performance metrics.
- Full host and guest traces and both summary outputs are saved under
  logs/part_c/.

perf status
-----------
- Host /proc/sys/kernel/perf_event_paranoid was 4.
- The bounded, unprivileged perf record attempt failed with exit status 255:
  the kernel denied access to CPU and software performance events.
- perf.data is 0 bytes; there is no valid perf recording and no perf report
  or CPU hotspot can be claimed.
- perf stat exited 0 but reported CPU counters as "<not supported>"; those
  counters are not measurements. The target did run, as shown in
  perf_stat_stdout.txt.
- The user approved a sudo perf attempt. The command could not authenticate
  because this execution environment requires an interactive terminal
  (sudo: A terminal is required to authenticate). Root perf access therefore
  remains untested; the failure is not evidence that the kernel blocks root.
- No package installation or host perf configuration change was made.
- No ARM perf executable was staged in the Part C guest; perf CPU profiling
  in QEMU is therefore not claimed.
